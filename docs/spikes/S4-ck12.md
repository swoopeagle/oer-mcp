# Spike S4 — CK-12 acquisition
**Date:** 2026-06-15 · **Verdict: NO-GO via accessible routes — every D17 premise fails**

D17 promoted CK-12 to a first-class Phase 1 source on four assumptions: (1) CC BY,
(2) carries CCSS tags → publisher-guide alignment seed, (3) structured FlexBook
text exposition, (4) free API. Checked against the actual data, **all four fail.**

## What was checked
CK-12 is on Learning Equality's Kolibri (channel `1d8f6d84618153c18c695d85074952a7`,
English, 10,643 resources) — the same clean route as Khan (D16). Downloaded and
inspected the channel DB; probed CK-12's own site.

## Findings
| Assumption (D17) | Reality |
|---|---|
| CC BY | **CC BY-NC** (10,629 of 10,651 nodes). Belongs in the NC DB, not the core CC BY DB. |
| CCSS tags → publisher seed | **None.** `content_contenttag` empty; no CCSS/standards refs in `categories` or `description`. Same as Khan. |
| Structured FlexBook text | **No extractable prose.** The html5 nodes are **PLIX interactive simulations** ("Base Ten Blocks (PLIX)") — zipped HTML/JS apps, not text. |
| Free API | CK-12.org returns **403** to non-browser requests (bot-walled like Khan). |
| (video transcripts, as a fallback like Khan) | **0 math videos with English VTT** in the export. |

Net: via every accessible route, CK-12 yields **nothing usable** for a text
retrieval layer — html5 isn't text, exercises are reference-only Perseus
(licensing, same as Khan), videos have no English transcripts.

## Consequence for the plan
- **D17 is void.** CK-12 should be dropped from Phase 1; building an adapter is wasted effort.
- The corpus is already strong without it: **OpenStax** (8,761 chunks, gr 6–college + K-5 arithmetic review) + **Khan transcripts** (~3,322, true K-12 incl. K-5). K-12 coverage is met.
- **The real open gap is the `publisher_guide` CCSS seed.** No accessible source (OpenStax S3, Khan S2, CK-12 S4) ships machine-readable CCSS tags, so Phase 1 alignment is entirely embedding-only. The schema's `publisher_guide` confidence tier currently has no data source.

## Options for the CCSS-seed gap (owner decision)
1. **Accept embedding-only for Phase 1.** Calibration (D18) already makes it usable; ship and revisit seeding later.
2. **gemma-verified alignment upgrade.** Have gemma judge high-confidence embedding alignments and promote confirmed ones to a higher-confidence tier (`alignment_source='llm_verified'`). Gets publisher-guide-like confidence without publisher guides; uses the inference we already run.
3. **Source CCSS alignments separately** (e.g. a CCSS crosswalk/correlation dataset) and import as `publisher_guide` rows. More research; uncertain availability.
